## What this project is

University master's project (BEEM063 Hackathon, Exeter MSc FinTech). **Team:** Transakt.
**Product:** **Blockmediary** — a programmable documentary escrow layer for SME
cross-border trade. Buyer prefunds stablecoin into escrow, seller ships and submits
trade documents, smart contract releases funds when documents satisfy the agreed
release rules. *LC-like trust for smaller deals.*

Explicitly **not** a financing / advances product — trade financing is out of MVP scope
(see [docs/product-blockmediary.md](docs/product-blockmediary.md) and the canonical
MVP doc at `Hackathon/MVP_FLOW.md` in Drive).

Backed by a team of AI agents; the shipped product will expose them through a
user-facing interface (web app / dashboard / chat) via the Claude API or
Agent SDK.

## Keeping the generated copies in sync

After editing anything in `agents/` or `skills/`, regenerate:

```
python tools/sync_agents.py
```

To check for drift (use this in pre-commit hooks / CI):

```
python tools/sync_agents.py --check
```

It exits non-zero and lists offending files if `.claude/` doesn't match canonical.

### Suggested pre-commit hook

Drop this in `.git/hooks/pre-commit` (and `chmod +x` on macOS/Linux):

```sh
#!/bin/sh
python tools/sync_agents.py --check || {
  echo
  echo "Blockmediary: canonical and generated specs are out of sync."
  echo "Run: python tools/sync_agents.py"
  exit 1
}
```

## The agent model

1. **Role** → each file in [agents/](agents/) is one specialist's system prompt.
2. **Workflow** → each `skills/<name>/SKILL.md` is one Trigger→Input→Process→Output flow.
3. **Memory/context** → [docs/domain-rules.md](docs/domain-rules.md) gives agents business rules and standards.
4. **Tools** → [tools/](tools/) + MCP connectors turn answers into actions.
5. **Routines** → scheduled or event-triggered (hooks in `.claude/settings.json` for Claude Code; equivalents per tool elsewhere).

## Working conventions

- This repo is the **agent scaffold only**. Non-code artifacts (proposal, thesis,
  reports, datasets, slides) live in Google Drive. The Google Drive MCP is wired
  through the user-scope claude.ai integration (no `.mcp.json` entry needed);
  **scope all Drive reads to the `Hackathon/` folder** — it's the only directory
  relevant to this project. Other MCP connectors for the downstream product
  (chain RPC, sanctions feeds, logistics aggregator) are wired in the product
  repo, not here.
- **Never use real customer/PII financial data.** Use Plaid/Stripe sandbox, public
  Kaggle datasets, or synthetic data only.
- One agent = one clear responsibility. Compose them via the orchestrator; don't
  bloat one agent.
- Every agent must state its inputs, outputs, and escalation/handoff rules.
- Keep money math deterministic — do it in `tools/`, not in agent free-text, to
  avoid LLM arithmetic errors.
- **Name branches by purpose.** Use `<type>/<kebab-purpose>` — `type` ∈
  {feat, fix, chore, ci, docs, refactor}, or `claude/` to mark an agent-authored
  branch — with a suffix that says what the branch does (e.g.
  `claude/tldr-morning-briefing`, `chore/remove-operations-agents`, `ci/pr-gates`).
  Never open a PR from a tool-generated random branch name
  (`claude/<adjective>-<name>-<hexid>`); rename to a purposeful branch off `main`
  first (stash → `git checkout -B <good-name> origin/main` → pop).
